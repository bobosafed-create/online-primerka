# StyleGlobe для селлеров — инструкция по запуску

Сервис каталожных фото для маркетплейсов (Wildberries, Ozon). Клиент загружает фото одежды,
получает первое превью бесплатно (с водяным знаком), покупает пакет генераций и по коду доступа
скачивает фото/видео в HD без водяного знака.

## ВАЖНО: куда деплоить

Этот сервис заменяет предыдущее приложение «Онлайн примерка» на ТОМ ЖЕ адресе:
**https://bobosafed-create-online-primerka-e314.twc1.net**

Адрес сохраняется специально — под него уже настроена реклама в Яндекс Директ, и на нём подтверждены
права в Яндекс Вебмастере (мета-тег `yandex-verification` уже вшит в главную страницу).
Поэтому загружайте эти файлы в тот же репозиторий / то же приложение Timeweb, что и раньше.

Старая версия («Онлайн примерка» за 99 ₽) сохранена в архиве `primerka-BACKUP-rozica-99r.zip` —
если понадобится откат, можно вернуть её файлы.

## Настройки приложения (переменные окружения в Timeweb)

Задавайте секреты ТОЛЬКО в панели Timeweb (Переменные окружения), НЕ в коде и НЕ в переписке.

| Переменная            | Назначение                                              | Обязательна |
|-----------------------|---------------------------------------------------------|-------------|
| `DATABASE_URL`        | Строка подключения PostgreSQL — **обязательно!**        | ДА          |
| `ADMIN_PASSWORD`      | Пароль в админку `/admin`                               | ДА          |
| `SITE_URL`            | https://bobosafed-create-online-primerka-e314.twc1.net  | ДА          |
| `WAVESPEED_API_KEY`   | Ключ WaveSpeedAI (генерация фото/видео)                 | ДА          |
| `YOOKASSA_SHOP_ID`    | ID магазина ЮKassa                                      | для оплаты  |
| `YOOKASSA_SECRET_KEY` | Секретный ключ ЮKassa                                   | для оплаты  |
| `APP_ENV`             | `production` на боевом сайте; запрещает тестовые заказы | ДА          |
| `SESSION_SECRET`      | Случайная строка не короче 32 байт для подписания сессий | ДА          |
| `ADMIN_SESSION_HOURS` | Срок серверной сессии администратора, по умолчанию 12 часов | нет |
| `TRUST_PROXY_HEADERS` | `1` только за доверенным reverse proxy Timeweb          | ДА          |
| `FREE_PREVIEW_IP_LIMIT` | Суточный лимит бесплатных превью с одного IP (по умолчанию 3) | нет |
| `FILE_TTL_HOURS`       | Срок хранения временных фото/результатов, по умолчанию 24 часа | нет |
| `ENABLE_TEST_ORDERS`  | Только для отдельного staging, никогда не для production | нет |
| `TEST_ORDER_SECRET`   | Секрет тестовых заказов только для staging              | нет         |

В production обязательно задайте `APP_ENV=production`. Endpoint тестовых заказов при этом закрыт независимо от
настроек админки. Не включайте `ENABLE_TEST_ORDERS` в production.

### Про `DATABASE_URL` — почему это критично

Балансы кодов доступа (сколько генераций осталось) хранятся в базе. Без `DATABASE_URL` сервер
использует **временную** базу, которая обнуляется при каждом перезапуске/передеплое — то есть
оплаченные клиентом генерации пропадут. Поэтому для продаж PostgreSQL **обязателен**.

Как подключить на Timeweb:
1. В панели Timeweb создайте базу данных PostgreSQL.
2. Скопируйте строку подключения (обычно вида `postgresql://user:pass@host:port/dbname`).
3. Вставьте её в переменную `DATABASE_URL` в настройках приложения. Сохраните и передеплойте.
4. Зайдите в `/admin` — вверху не должно быть предупреждения о временной базе.

## Запуск

- Для воспроизводимой установки используйте `pip install -r requirements.lock`.
- Команда запуска: `uvicorn main:app --host 0.0.0.0 --port 8000`
- До внедрения внешней очереди запускайте ровно один worker. При рестарте незавершённые reservation автоматически возвращаются.
- Проверка здоровья (healthcheck): `/api/health`
- Python 3.13
- При старте схема БД обновляется только последовательными миграциями из таблицы `schema_migrations`. Ошибка миграции останавливает production-запуск.

## Как тестировать перед боем

Автоматические проверки не обращаются во внешнюю ЮKassa и не создают платежи:

```text
python -m unittest discover -s tests -v
python -m pip check
```

Для настоящего платежа в тестовой среде ЮKassa используйте отдельный staging-сайт:

1. Задайте `APP_ENV=staging`, тестовые `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` только в защищённых переменных staging.
2. Оставьте `ENABLE_TEST_ORDERS=0` и выключите внутренний «Тестовый режим»: он специально отключает ЮKassa.
3. Укажите webhook staging-сайта: `/api/yookassa/webhook`. Не направляйте тестовые уведомления на production.
4. Пройдите путь оплаты тестовой банковской картой ЮKassa и вернитесь на сайт.
5. Проверьте: заказ отмечен оплаченным, выдан ровно один код, сумма/валюта/ID платежа совпадают, повторный webhook не создаёт второй код.
6. Проверьте расход и возврат кредита при успешной и неуспешной генерации.

Тестовые ключи нельзя сохранять в `.env`, GitHub, скриншотах или переписке. Автоматический deployment этим репозиторием не выполняется.
